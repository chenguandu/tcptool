# TCP 调试工具 - JT808 / 通用TCP

一个基于 Rust + egui 的 TCP 调试工具，支持 **JT/T 808-2013**、**JT/T 808-2019** 协议以及 **通用 TCP 透传**，用于 GPS 车辆终端 / 平台对接的调试与测试。

## 功能特性

### 核心功能
- **TCP 连接管理** — 支持多连接并行管理，实时状态显示（已连接/已断开/连接中）
- **多协议模式** — JT808-2013 / JT808-2019 / 通用TCP 三种模式可选
- **JT808 协议编解码** — 完整支持 JT/T 808-2013、JT/T 808-2019；接收方向按消息体属性 bit14 自动识别协议版本（bit14=0 → 2013，bit14=1 → 2019），识别结果自动传递到后续自动发送
- **自动心跳** — 可配置心跳间隔，支持暂停/恢复，保持长连接（通用TCP模式不发送）
- **快捷指令** — 内置常用 JT808 指令，支持自定义指令；发送时按当前连接的协议版本与设备 SN 重新组帧
- **终端注册流程** — 一键模拟终端注册、鉴权、心跳完整流程
- **终端通用应答** — 选中接收报文后一键回复 0x0001（流水号/消息ID 取自已选报文）

### 协议模式
| 模式 | 说明 |
|------|------|
| **JT808-2013** | 6 字节终端 SN（12 个十六进制字符），消息头 12 字节 |
| **JT808-2019** | 消息体属性后增加 1 字节协议版本号（固定 1），10 字节终端 SN（20 个十六进制字符，不足左侧补 0），消息头 17 字节；平台按 bit14 自动识别 |
| **通用TCP** | 发送内容原样发出，不解析、不组帧、不发送心跳，适合透传/自定义协议调试 |

### 2013 与 2019 协议差异
| 项目 | 2013 | 2019 |
|------|------|------|
| 消息头 | 12 字节 | 17 字节（协议版本号紧跟消息体属性） |
| 终端手机号/终端SN | 6 字节（12 个十六进制字符） | 10 字节（20 个十六进制字符，不足前置补 0，解码去掉前导 0） |
| 终端注册 0x0100 | 制造商ID 5 / 终端型号 20 / 终端ID 7 | 制造商ID 11 / 终端型号 30 / 终端ID 30 |
| 终端鉴权 0x0102 | 鉴权码字符串 | 鉴权码长度 + 鉴权码 + IMEI(15) + 软件版本号(20) |
| 参数项 0x8103 | 参数ID + 参数长度 + 参数值 | 同左 |
| STRING 字段 | GBK 编码 | GBK 编码 |

### 界面布局
- **左栏** — 连接列表（新建/编辑/删除/双击自动连接）
- **中栏** — 报文流展示（自动滚动到最新，显示协议版本）
- **右栏** — 报文详情解析 + 快捷指令面板（显示当前组帧版本与 SN）
- **底部** — 多行发送输入框（支持 HEX/文本/GBK/UTF-8 编码）

### 数据管理
- **SQLite 持久化** — 连接配置（协议版本、SN、IMEI、软件版本号）、报文日志、自定义指令自动保存
- **报文导出** — 支持 JSON/CSV 格式导出（含协议版本字段）
- **多编码支持** — GBK/UTF-8/ASCII/HEX 编码切换

### 已支持的 JT808 消息类型
| 消息ID | 名称 | 方向 |
|--------|------|------|
| 0x0001 | 终端通用应答 | 终端→平台 |
| 0x0002 | 终端心跳 | 终端→平台 |
| 0x0100 | 终端注册 | 终端→平台 |
| 0x0102 | 终端鉴权 | 终端→平台 |
| 0x0107 | 查询终端属性应答 | 终端→平台 |
| 0x0200 | 位置信息汇报 | 终端→平台 |
| 0x8001 | 平台通用应答 | 平台→终端 |
| 0x8100 | 平台注册应答 | 平台→终端 |
| 0x8103 | 参数设置 | 平台→终端 |
| 0x8300 | 文本信息下发 | 平台→终端 |
| 0x8500 | 车辆控制 | 平台→终端 |

## 构建与运行

### 前置条件
- Rust 1.75+
- Windows (当前仅支持 Windows)

### 构建
```bash
# Debug 构建
cargo build

# Release 构建
cargo build --release

# 运行
cargo run --release
```

Release 二进制位于 `target/release/TcpTool.exe`

### 测试
```bash
cargo test
```

## 使用说明

### 快速开始
1. 点击 **"新建连接"** 配置服务器地址（默认端口 5100）
2. 选择 **协议版本**：
   - `JT808-2013` / `JT808-2019`：发送按所选版本组帧，接收按 bit14 自动识别
   - `通用TCP`：发送内容原样发出，不做任何修改
3. 填写 **终端手机号/SN**（2013 版 12 个十六进制字符，2019 版 20 个十六进制字符）
4. JT808-2019 模式建议填写 **终端IMEI** 和 **软件版本号**（鉴权时使用，默认 `V1.0.0`）
5. 点击 **"连接"** 建立 TCP 连接
6. 点击 **"完整注册流程"** 自动完成注册→鉴权→心跳

协议版本也可以在工具栏的「协议」下拉中随时切换，修改会立即同步到运行中的连接。

### 快捷指令
- **内置指令**：心跳、注册、通用应答、鉴权、位置汇报，均按当前连接的协议版本 + 设备 SN 组帧
- **自定义指令**：
  - 填写完整 JT808 帧时，发送前自动按当前版本 + 设备 SN 重新组帧（消息体按目标版本重编码）
  - 填写「消息ID + 消息体」时，直接按当前版本 + SN 组帧
- **通用TCP模式**：内置 JT808 指令隐藏，自定义指令与发送框内容原样发送

### 数据持久化
连接配置和快捷指令自动保存到 `tcptool.db`（SQLite），下次启动自动加载；旧版本数据库会自动迁移新增字段（协议版本、IMEI、软件版本号）。

## 项目结构
```
src/
├── main.rs           # 入口，窗口配置，字体加载
├── lib.rs            # 模块声明
├── app.rs            # 主应用状态 + egui UI
├── connection.rs     # TCP 连接管理 (tokio 异步)
├── protocol/
│   ├── mod.rs
│   ├── codec.rs      # JT808 编解码（转义/校验和）
│   ├── message.rs    # 消息结构体 & 解析器（2013/2019 差异）
│   ├── types.rs      # 消息头/终端SN/BCD/协议版本/常量
│   └── builder.rs    # 消息构建器
├── db/
│   ├── mod.rs        # SQLite CRUD
│   └── schema.rs     # 数据库表结构
└── ui/               # UI 组件
```
